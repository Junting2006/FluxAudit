# FluxAudit · PDPO 隐私合规说明（香港《个人资料（私隐）条例》）

> 本文件由成员 1 维护，是提交材料「技术与合规说明」的组成部分。
> 适用语境：AIx Origin Summit · 香港会场。最后更新：2026-09-04

---

## 一、核心结论（一句话）

**FluxAudit 的演示与测试全程不收集、不处理任何个人资料**；所使用数据仅为公开链上数据、合成数据与已脱敏数据，符合香港《个人资料（私隐）条例》（Cap. 486，下称"条例"）的适用范围界定。

## 二、数据收集（条例第 1 保障原则：收集目的与方式）

| 数据类型 | 是否个人资料 | 说明 |
|---|---|---|
| 用户输入的合约地址 / 白皮书 / 财务文件 | 否（公开或合成） | 演示与测试均使用合成项目数据，白皮书每页标注"合成演示数据" |
| 测试网链上数据（Sepolia RPC） | 否 | 公开区块链数据 |
| Etherscan API 公开数据 | 否 | 公开接口数据 |
| 用户钱包地址（用于上链锚定） | 视情况 | 仅用于发起测试网存证交易；不入库、不分析、不关联其他资料 |
| 姓名 / 电话 / 邮箱等 | **不收集** | 产品无注册、无登录、无埋点收集个人资料 |

## 三、数据用途与保留

- **用途单一**：数据仅用于执行审计任务、生成报告与链上存证演示，不作任何二次营销或画像。
- **保留政策**：审计任务数据仅在演示运行期间暂存于本地/内存，演示结束后清理；测试记录仅保留脱敏统计（任务次数、耗时、成败），不含报告原文与输入原文。

## 四、数据安全（条例第 4 保障原则）

- 报告全文不上链，链上仅存 keccak256 哈希——**任何链上记录均不可逆推出报告内容**。
- API Key、私钥不入仓库；提交前执行 secret scan（红线要求）。
- 推理日志 JSON 仅在本地可信环境留档，供演示复核，不外发。

## 五、跨境传输（条例第 33 条，如实披露）

| 路径 | 是否出境 | 说明 |
|---|---|---|
| 调用 LLM API（OpenAI 兼容） | **是（可能）** | 提交内容为公开/合成文本，**不含个人资料**；正式部署将评估本地模型或 TEE 方案 |
| 测试网 RPC / Etherscan API | 是 | 公开链上数据 |
| 用户个人资料 | **不出境** | 因为根本不收集 |

> 答辩口径：我们如实披露云端依赖与可能的数据跨境路径；由于全程不涉及个人资料，条例的跨境传输限制不构成合规障碍。

## 六、条例适用性声明

1. 条例规管对象为"个人资料"（可直接或间接识辨在世人士的资料）。FluxAudit 演示数据不含任何此类资料，故产品演示行为**不落入条例主要条文规管范围**。
2. 若未来接入真实客户数据，需另行完成隐私影响评估（PIA）、数据收集声明（PICS）与跨境传输保障——已列入路线图的合规前置项。
3. 本说明由团队合规负责人（成员 1）确认；如有更新，以提交版本为准。
