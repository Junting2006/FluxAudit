# FluxAudit 项目说明

最后更新：2026-09-04

## 1. 问题

Web3 项目尽调经常依赖白皮书、官网和人工阅读，但关键风险通常藏在链上：团队钱包真实占比、锁仓是否真的存在、流动性是否可撤、资金是否流向高风险地址。普通用户很难同时读懂文档和链上数据，也很难判断报告有没有被事后篡改。

## 2. 目标用户

- Hackathon 评委演示场景：快速看到 AI 推理、链上核验和哈希证明闭环。
- Web3 投资者 / DAO 成员：初步判断项目是否存在明显信息不一致。
- 审计或风控团队：把人工尽调前的资料整理和风险初筛自动化。

## 3. 方案

FluxAudit 是一个 AI 辅助链上尽调工具。用户提交项目白皮书文本和合约地址后，系统执行三段流程：

1. DocAgent 提取文档声明，例如团队占比、锁仓、审计声明和收益承诺。
2. ChainAgent 拉取或模拟链上事实，例如持币集中度、TimeLock、流动性锁定、源码相似度和资金流。
3. CrossCheckAgent 与 RiskAgent 对比文档和链上数据，输出结构化风险分、findings、证据和推演日志。

最终报告会生成 step_hash、Merkle Root 和 report_hash，供成员5上链锚定，前端可重新计算并验证报告完整性。

## 4. AI 承重点

- DocAgent 负责把非结构化白皮书转成结构化 JSON。
- CrossCheckAgent 把文档声明与链上字段逐项比较。
- RiskAgent 根据风险规则输出 overall_risk_score、risk_level 和 risk_reasons。
- Reasoning Log 按步骤输出，可被 SSE 实时推送给前端。

当前实现默认使用确定性规则引擎，保证无 API Key 也能演示；启用 DeepSeek 时，LLM 只负责文档解析，交叉校验与打分仍由规则引擎执行，避免链上硬指标漏报。

## 5. 链上承重点

- ChainAgent 提供团队钱包占比、头部地址集中度、TimeLock、合约验证、流动性锁定、源码相似度、审计报告可验证性和资金流异常字段。
- 成员4报告层生成 reasoning_step_hashes、backend_step_hashes、merkle_root 和 report_hash。
- 成员5合约只需保存 reportHash、merkleRoot、riskScore，实现链上真实性锚定。

## 6. 当前演示结果

- NovaPay 高风险样例：85 分，HIGH，6 条 findings。
- AtlasIndex 合规样例：2 分，LOW，1 条 finding。
- SSE 步骤：INPUT_VALIDATED、CHAIN_FETCHED、DOC_PARSING、CROSS_CHECKING、RISK_SCORING、REPORT_ASSEMBLED、MERKLE_ROOTED、REPORT_HASHED。

## 7. 技术栈

- 成员3：Python、OpenAI SDK 兼容 DeepSeek、pycryptodome、规则引擎。
- 成员4：FastAPI、SSE、Etherscan API / Mock Fallback、pycryptodome。
- 成员5：Solidity、Hardhat、ethers.js、Sepolia 测试网。

## 8. 诚实边界

当前版本用于 Hackathon 演示和公开 / 合成数据测试，不构成投资建议。Mock 数据、LLM 云端依赖、人工钱包确认和 Sepolia 测试网锚定都需要在路演中如实披露。
